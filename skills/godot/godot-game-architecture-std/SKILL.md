# Godot 4 游戏系统架构规范

AI 必须严格遵守此架构规范组织模块、划分职责并实现系统交互。

---

## 核心架构原则

1. **职责单一（SRP）与禁止上帝类**：任何逻辑系统仅负责本领域的计算与内存维护（如数值系统仅算属性、装备系统仅管穿脱）。严禁将所有玩家状态与计算逻辑堆叠在单个全局类中。
2. **单向数据流与数据安全**：外部节点仅能通过公开的只读方法获取计算结果，严禁外部越权直接修改子系统内部成员变量。
3. **向下调用，向上信号**：父节点/管理系统直接调用子节点方法；子节点/底层实体通过信号向上汇报，绝对禁止跨层级反向引用父节点。
4. **事件驱动被动解耦**：基础服务（音效、震动、广告等）作为信号总线的下游被动监听者，业务代码严禁主动调用音效/广告播放接口。
5. **双总线隔离与生命周期安全**：全局生命周期事件与单局战斗高频事件严格分流，换关时统一重置局内状态，防止野指针回调。

## 系统分层与 Autoload 拓扑

项目 Autoload 单例必须按以下依赖层次从上到下加载：

| 层级 | 单例名称 | 核心职责 | 依赖关系 |
| :--- | :--- | :--- | :--- |
| **基础通信层** | `全局信号总线` | 跨场景、大粒度系统事件中继（游戏流程、全局结算、通用系统通知） | 无依赖 |
| | `局内信号总线` | 单局对局内实体交互事件中继（伤害、刷怪、拾取、波次），提供重置协议 | 无依赖 |
| **静态数据层** | `配置数据仓库` | 启动时解析导表工具生成的 JSON，转为只读内存字典并提供强类型查询 | 无依赖 |
| **领域业务层** | `玩家数值系统` | 维护玩家基础属性，统筹最终攻防数值计算，向外派发属性变更信号 | 依赖全局总线 |
| | `玩家装备系统` | 维护槽位与穿脱逻辑，计算装备加成并单向推送至数值系统 | 依赖配置仓库、数值系统 |
| | `其他业务子系统` | 背包、天赋、任务等独立自治子系统 | 视业务而定 |
| **持久化层** | `存档持久化器` | 汇总各业务子系统导出的数据字典，直接执行 `user://` 文件的读写 | 依赖各业务子系统 |
| **展示与驱动层** | `界面管理器` | 多 `CanvasLayer` 管控常驻 HUD、功能窗口、模态弹窗栈与全局提示 | 依赖全局/局内总线 |
| | `场景管理器` | 关卡与主界面的异步切换、转场遮罩调度及局内总线生命周期重置 | 依赖界面管理器、局内总线 |
| **解耦服务层** | `音效监听服务` | 纯被动监听信号总线，负责音频播放与频次调度 | 依赖全局/局内总线 |
| | `触觉与广告服务` | 纯被动监听信号总线，负责震动触发与 SDK 广告弹窗唤起 | 依赖全局/局内总线 |

## 各核心模块规范

### 1. 信号总线系统规范
* **全局信号总线**：仅定义跨场景、全局流程相关信号（如 `游戏开始`、`关卡完成`、`金币发生变更`）。
* **局内信号总线**：
  * 仅定义对局内部实体的高频交互信号（如 `实体受到伤害`、`掉落物被拾取`、`波次开始`）。
  * 必须提供 `重置局内状态()` 方法，由场景管理器在换关或重启时强制调用，避免旧信号残留。

### 2. 静态配置数据规范
* 策划配置采用 XLSX 维护，经由外部导表工具导出为 `.json` 文件。
* 统一由 `配置数据仓库` 在启动时一次性加载入内存，解析为只读字典。
* 严禁业务脚本直接通过 `FileAccess` 读取配置，必须通过 `配置数据仓库.获取XX配置(标识)` 统一获取。

### 3. 分层界面与弹窗规范
`界面管理器` 必须统一维护 4 层 `CanvasLayer`（数值由低到高），确保层级不发生穿透冲突：
* **Layer 10（底层HUD层）**：常驻资源栏、虚拟摇杆、技能按键等。
* **Layer 20（窗口层）**：背包、角色属性等全屏/半屏非模态界面。
* **Layer 30（模态弹窗层）**：奖励弹窗、结算面板、确认对话框。必须包含全屏事件拦截遮罩（`mouse_filter = MOUSE_FILTER_STOP`），并以栈结构（`_当前弹窗栈`）维护后进先出关闭逻辑。
* **Layer 40（全局提示层）**：Toast 飘字、Loading 转场遮罩。

### 4. 被动监听解耦服务规范
* 业务代码（如玩家受击、拾取金币）仅需向信号总线派发事件：`局内信号总线.实体受到伤害.emit(目标, 伤害数值)`。
* 音效、震动、打点系统严禁暴露命令式接口供业务层调用，必须在 `_ready` 中被动订阅总线信号并自行决策表现逻辑。

### 5. 领域子系统与组合式存档规范
* **领域自治**：每个业务系统（数值、装备、背包）为独立的 Autoload，全权负责自身的业务逻辑计算与内存数据。
* **数据流动规范**：装备系统计算加成后调用 `玩家数值系统.设置附加攻击力(加成值)`，数值系统重新汇总并发出 `玩家属性发生变更` 信号，UI 监听该信号刷新显示。
* **统一存档契约**：每个需要持久化的子系统必须强制实现两个标准化接口：
  - `func 导出存档数据() -> Dictionary`
  - `func 导入存档数据(数据字典: Dictionary) -> void`
* **直接落盘**：`存档持久化器` 仅负责在保存时向各子系统收集数据字典，汇总后序列化直接写入 `user://` 文件；加载时读取文件并分发给各子系统还原状态。
