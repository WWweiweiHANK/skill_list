# 轻量街机 UI

先读取目标界面、当前项目规范和用户本次修改要求。以现有可验证布局为依据；不要把本项目规范自动套用到《雪下的人》或其他项目。

## 视觉

使用简洁圆角或轻微斜切、粗深色描边、深蓝黑内底，少量低多边形切面与高光。保持休闲手游、轻像素街机感；以平面色块为主。
避免厚重金属、复杂机械边框、过度霓虹光晕、复杂纹理、大面积高饱和色和无意义装饰。不添加 CRT 或 Shader 效果；保留必要字体描边。

## 颜色语义

| 颜色 | 功能 |
| --- | --- |
| 蓝色 | 系统、导航、中性功能 |
| 橙色 | 可执行、购买、确认、领取 |
| 灰色／灰蓝 | 禁用、不可购买、未解锁、条件不足、次要信息 |
| 黄色／金色 | 金币、奖励、资源、进度、重要数值 |
| 绿色 | 提升、升级；升级按钮优先绿色 |
| 白色 | 高可读正文与数值 |
| 黑色／深蓝黑 | 内底、描边、对比 |

升级也是可执行操作时优先保留绿色升级语义，普通确认或领取用橙色。不可用状态使用灰化或遮罩，并保留条件信息。不要仅凭颜色区分交互状态；结合图标、标签和状态变化。

## 布局与实现

处理 Godot 布局时读取 [项目布局基准](references/project-layout.md)。先检查真实节点和安全区域，再应用基准；发现过时尺寸或重叠时报告冲突，不强行覆盖用户的新布局。
按钮、面板、页签和进度条优先复用现有组件与 Theme。保留可读文字、点击区域和不同屏幕比例下的层级。
制作独立 UI 资产时按用途命名，透明背景、干净边缘；默认不把文字数字烘焙进底图，文字交给引擎渲染。检查素材背景是否真正透明。
审查时指出具体元素、违反的语义或可读性问题、最小修正。实现后按可用工具检查正常、禁用、选中和长文本状态；未运行 Godot 时明确说明验证范围。
